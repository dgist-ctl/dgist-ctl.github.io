🏫 DGIST In-House Case
1

AI Generates Lecture Notes, Slides, and Assignments through a Single Pipeline — A DGIST Faculty's Empirical Framework

Professor Minseok Jeon (PLX Lab, Department of Electrical Engineering and Computer Science) of DGIST presented "A Framework for AI-Assisted Course Material Generation" at the in-house AI utilization competition at DGIST on November 4, 2025, in the Education & Research category, and received the Idea Award. The framework chains ChatGPT, Windsurf, and Claude Code in sequence to generate foundational text (lecture notes), slides, and assignments through a single automation pipeline. The Data Structures course served as the empirical application; the presentation slides themselves were also produced by this framework.

  • Course content structured as Markdown (.md) → used as a single source from which slides and assignments are derived
  • Stage-optimized AI tool combinations: foundational text (ChatGPT + Windsurf) → slides (Claude Code + Beamer) → assignments (Claude Code)
  • Generated code and course pages fully published on GitHub, externally reproducible

Source: Jeon, M., A Framework for AI-Assisted Course Material Generation, Nov 4, 2025 · [Media]DGIST DNA (student newspaper), Nov 22, 2025

⚙ Three-Stage Framework
2

Stage 1 — Structure the Entire Course as a Markdown Knowledge Base with ChatGPT + Windsurf

The goal of Stage 1 is to generate the entire course content as Markdown (.md) documents. ChatGPT is prompted to produce a learning roadmap in Markdown format, yielding the overall course structure (Roadmap.md). Then, Windsurf — an AI-powered development environment — uses its Cascade Code agent to sequentially generate per-topic detail files. The result is a set of unit-level .md files (Arrays, Stacks, Trees, etc.) under the DataStructure/topics/ folder.

  • ChatGPT prompt: "I want to learn what data structures are... Would you please create a Learning Roadmap for me? Please describe the Roadmap using markdown format."
  • Windsurf prompt: "This is a learning roadmap. Create a list of markdown files for each topic. For each topic, write an introduction and list of knowledge points."
  • Tools: ChatGPT (conversational AI for roadmap ideation) + Windsurf (AI-powered development environment for automated Markdown authoring)

Source: Jeon, M., A Framework for AI-Assisted Course Material Generation, Nov 4, 2025 · Original PDF

3

Stage 2 — Generate Professional Lecture Slides as Code with Claude Code + Beamer LaTeX

In Stage 2, lecture slides are generated based on the Markdown knowledge base from Stage 1. The framework combines Beamer (a LaTeX slide class for academic and professional presentations, using the CleanEasy template) with Claude Code. Claude Code is launched at the project root (DataStructure/), and the /init command primes it on the entire codebase; the system then generates slide files (.tex) using the specified Markdown content and Beamer template. The output is a slide set in academic presentation format, available with .tex sources in the slides/ folder of the GitHub repository.

  • Core Claude Code prompt: "Based on the contents of topics/Stack.md, referencing the slides/BeamerTemplate, generate slides/Stack/stack.tex"
  • Beamer-based output optimized for STEM lecture formats: equations, code blocks, multi-column layouts
  • Workflow: create slides/ folder → choose Beamer template → launch Claude Code → /init → submit slide-generation prompt

Source: Jeon, M., A Framework for AI-Assisted Course Material Generation, Nov 4, 2025 · Original PDF

4

Stage 3 — Auto-Generate Implementation Assignments, Application Code, and Tests with Claude Code

In Stage 3, assignments are generated from the same Markdown knowledge base and slides. Claude Code was instructed: "Generate stack.py implementing the core stack functions, and application.py that uses them; later, hide the core functions to turn this into a student assignment." The output is a complete assignment package consisting of four files: README.md, stack.py, application.py, test_stack.py.

  • Core Claude Code prompt: "Implement the core stack functions in stack.py, and write code in application.py that uses them. The core functions will later be hidden for use as a student assignment."
  • test_stack.py establishes the basis for automated grading; README.md auto-generates the assignment description
  • Notes → slides → assignments are derived from a single source (Markdown), ensuring structural consistency (cognitive load suitability of the fill-in-the-blank task is discussed in the Editorial Lens, Sweller item)

Source: MinseokJGit/DataStructure, GitHub, 2025 · Jeon, M., Course Material Generation Framework, Nov 4, 2025 · Original PDF

💡 Methodology and Design Principles
5

A Common Prompt Pattern Across All Three Stages: “Context First, Structure Explicit, File Names Specified”

Professor Jeon's prompts follow a consistent structure: ① first describe the course currently being taught and the source location, ② specify the file/folder structure the AI must reference, and ③ explicitly indicate the desired output's filename and storage path. This pattern provides sufficient context for the AI, eliciting consistent outputs. Priming the entire project context in advance via Claude Code's /init command is central.

  • Common structure: "I am currently teaching [course] based on [source location] → reference [files] → generate [output filename]"
  • A single-codebase structure where all artifacts derive from one root (DataStructure/) is the key to consistency
  • The pattern is not limited to Data Structures; it applies to any course whose content can be structured in Markdown

Source: Jeon, M., A Framework for AI-Assisted Course Material Generation, Nov 4, 2025 · Original PDF

6

Efficiency × Quality × Scalability: Three Values This Framework Demonstrates

The core values presented by Professor Jeon are Efficiency (time savings) × Quality (professional outputs) × Scalability (transferability to other courses and formats). The framework was piloted in Data Structures, with the generated course page and code published on GitHub. In 2026, the “Automated Lecture Notes and Slides Generation” seminar and the “How to Learn Course Content Using AI” seminar are also planned, expanding to both faculty and students.

  • Efficiency: repetitive tasks of separately producing notes/slides/assignments are converted into an automated pipeline
  • Quality: professional LaTeX/Beamer slides, Python assignment code, and even auto-grading test code are generated automatically
  • Scalability: per the presenter's plan, extension is planned to other courses (CSE307 Programming Languages, IC637 Program Analysis) and to academic presentation materials
Caveat — The above values are an evaluation at the materials-output dimension; learning-outcome data (exams, transfer, satisfaction) and the pedagogical-innovation dimension (active learning, formative assessment, self-regulated learning) lie outside the scope of this presentation. For Efficiency × Quality × Scalability to translate into learning effects, the time saved must be reinvested in learning-activity and feedback design (see the Integrated Assessment in the Editorial Lens for details).

Source: Jeon, M., Data Structures (AI-generated course page), DGIST PLX Lab, 2025 · MinseokJGit/DataStructure, GitHub

⚠ Extension and Limits
7

The Framework Is Already Public as a Three-Tier Seminar — Self-Paced Learning Paths by Skill Level

Professor Jeon released this framework as the 2026 PLX Lab seminar “Claude Code for Automated Lecture Notes and Slides Generation.” The seminar offers a three-tier learning path based on Beamer/Claude Code experience, allowing step-by-step access from setup guides to advanced applications. The presentation slides themselves were generated through this pipeline, and the generated lecture code and course pages are also publicly available.

  • Level 1 (Beginner): newly installed Claude Code or Beamer-inexperienced → produce one set of lecture notes/slides via step-by-step guide
  • Level 2 (Intermediate): Beamer-experienced → combine existing Beamer materials with Claude Code, transitioning to an auto-generation workflow
  • Level 3 (Advanced): current users of Beamer/Claude Code/AI editors → advanced use of the full pipeline (linked with the ep9 external resource)

Source: Claude Code for Automated Lecture Notes and Slides Generation, PLX Lab, 2026

8

Three Limits to Check Before Adopting This Framework As-Is

This framework is an empirical case optimized for DGIST's STEM context; the following must be checked before general adoption. First, verifying the content accuracy of AI-generated notes, slides, and assignments remains the instructor's responsibility. Second, the Beamer + LaTeX environment may pose installation/configuration entry barriers for non-experts. Third, licensing and cost implications of using Claude Code (paid) and Windsurf must be reviewed.

  • AI content error verification: technical accuracy, currency, and presence of references must be checked
  • Alternative tools for non-LaTeX users (Markdown+Marp, Google Slides automation, etc.) should be considered
  • For DGIST members, AI-tool access rights, cost-support policies, and data-security policies should be verified
  • Scope limitation: this case is an empirical application by a LaTeX/Beamer-skilled instructor in a code-based STEM course (Data Structures); transferability to humanities, social sciences, experimental sciences, or the arts requires separate validation
  • Possible double-automation loop (instructor−AI−student−AI) — AI-use scope and source-attribution standards should be specified in advance in assignment instructions (full analysis in the Editorial Lens)

Source: DGIST CTL internal review

🔎 Editorial Lens

We examine this case through educational-theory lenses. The criterion is not instructor efficiency but whether learning actually takes place. The core diagnosis of this issue is the conditions for transitioning from Materials Generation to Teaching Innovation.

Vygotsky — Scaffolding and Cognitive Internalization

Auto-generated materials do not directly replace the instructor's in-class scaffolding within the ZPD (Zone of Proximal Development). However, the act of an instructor authoring materials is itself a cognitive experience of internalizing the content. When that process is shortened, the capacity to detect and intervene on student misconceptions in real time may also weaken. Materials preparation and teaching capability are not separable.

[Research]Vygotsky, L. S. (1978). Mind in Society. Harvard University Press.

Hattie — The Distance Between Material Quality and Learning Effect

In Hattie's meta-analysis (2009), the effect size of instructional materials is about 0.4. Teacher feedback (0.70) and explicit teaching (0.57) are higher. Professional slides are not a sufficient condition for learning effects. Only when the time saved by this framework is reinvested in in-class feedback and interaction can learning effects be realized.

[Research]Hattie, J. (2009). Visible Learning. Routledge.

Biggs — Automation Without Constructive Alignment

Biggs's Constructive Alignment requires that learning objectives, learning activities, and assessment be coherently linked. In this framework, the "learning roadmap" generated by ChatGPT substitutes for learning objectives, but whether it aligns with DGIST's actual curricular performance goals is unverified. Structurally consistent materials do not automatically answer the question of what students must be able to do.

[Research]Biggs, J. (1996). Enhancing teaching through constructive alignment. Higher Education, 32(3), 347–364.

Sweller — Cognitive Load and Task Design

In Sweller's Cognitive Load Theory, effective task design follows the sequence: worked example → gradual fill-in-the-blank → independent problem solving. Whether the AI-generated stack.py "core function hiding" approach corresponds to a particular stage in this sequence — and whether it is calibrated to students' prior knowledge and cognitive level — is not guaranteed by automation. Formal completeness of materials does not guarantee cognitive optimization.

[Research]Sweller, J. (1988). Cognitive load during problem solving. Cognitive Science, 12(2), 257–285.

Integrated Assessment — TPACK · SAMR · Active Learning

TPACK (Mishra & Koehler · Technology · Pedagogy · Content) — the case is strong in Technology Knowledge, but changes in the Pedagogical Knowledge dimension (designing active-learning activities, formative assessment, self-regulated-learning support) lie outside the scope of automation.

SAMR (Puentedura · Substitution → Augmentation → Modification → Redefinition) — this case sits at the Augmentation stage of materials-production labor; transitioning to the Redefinition stage that newly defines the learning experience requires separate design.

Bloom Cognitive Levels — fill-in-the-blank tasks concentrate at the Apply level; activities at the Analyze, Evaluate, and Create levels must be supplemented by separate design.

In sum, this framework constitutes Teaching Materials Generation; for it to translate into Teaching Innovation, the time saved must be reinvested in the design of active learning, formative assessment, and feedback.

[Research]Mishra, P., & Koehler, M. J. (2006). TPACK. Teachers College Record, 108(6) · Puentedura, R. R. (2006). SAMR Model · Anderson, L. W., & Krathwohl, D. R. (2001). A Taxonomy for Learning, Teaching, and Assessing. Longman.

Academic Integrity — The Double Loop of AI-Made Tasks Solved by AI

The most immediate pedagogical issue raised by this framework is academic integrity. If a student solves an AI-generated stack.py task (with test_stack.py auto-grading) using Copilot, ChatGPT, or similar tools, an instructor−AI−student−AI double-automation loop forms. Auto-grading does not block this loop, and the presentation does not explicitly address this issue. Instructors operating AI-generated tasks should specify in advance, in the assignment instructions, ① the permitted scope of AI use, ② standards for citing AI in student submissions, and ③ whether the grading criteria are AI-friendly.

[CTL Review]DGIST CTL internal review · Reference: UNESCO (2023). ChatGPT and Artificial Intelligence in Higher Education: Quick Start Guide. UNESCO.
